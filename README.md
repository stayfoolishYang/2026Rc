# STM32 麦轮小车与机械臂控制工程

本仓库包含 STM32F103ZE 麦轮底盘/机械臂固件、Keil 工程、上位机串口接口，以及可视化硬件调参工作台。当前正式固件入口是 `USER/chassis_controller_main.c`。

当前源码基线为固件 `v181`。已恢复舵盘侧取物／放物的末段缓降，保留用户当前摄像头标定（mode84为36mm，mode85为18mm）；任务2从盘取杯仍按原逻辑使用普通速度。mode5/6毫米微调现在跟随87/88配置：mode87慢速400μs、mode88及上电默认快速200μs。任务2领奖台放置高度与摄像头打靶高度已拆开：mode33／34继续使用55／37mm，mode84／85分别升到当前标定36／18mm。升降有效上限为360mm，调参台共182项参数。mode 52 单独将 Servo1 收回到舵盘对位标定（当前2455 us）。保留底盘 mode 1/5 前后、mode 2/6 横移映射，独立元器件测试协议（mode 90–95）及 mode 71 单独闭合夹爪命令。上电时夹爪和底部转台 PWM 通道均保持为 0，不再自动松爪或回到 24°；其余初始化包括 Servo1 收回、陀螺仪、升降 GPIO、底盘、串口和 PE6 输入，不包含上电自动升降、自动抓放、自动移动或一次性参数候选分支。mode 80/81/82/83 是调参工作台长期使用的受限试动接口，mode 126 是保留的陀螺仪诊断接口，均不属于上电自动测试；mode 89 启用比赛启动后会锁定舵机试动和元器件运动测试。

## 仓库结构

- `USER/Template.uvprojx`：Keil MDK 工程。
- `USER/chassis_controller_main.c`：UART1 指令监听、麦轮运动、升降、舵机、任务动作和陀螺仪逻辑。
- `HARDWARE/`、`SYSTEM/`、`CORE/`、`STM32F10x_FWLib/`：硬件驱动、系统支持、启动文件和 STM32 标准库。
- `stm32_hardware_tuning_gui.py`：参数读取/写回、串口试动、编译、导出 BIN 和烧录工作台。
- `upper_host_v86/`：供树莓派或其他上位机调用的 Python 串口接口。

`OBJ/`、`USER/Listings/`、`__pycache__/`、BIN、Keil 中间文件和日志均为生成物，不提交到 Git。

## 硬件与工具

- STM32F103ZE High-density，512 KiB Flash。
- Keil MDK-ARM 5.x，ARMCC 5.06 工具链，STM32F1xx DFP。
- Windows Python 3.10 或更高版本。
- Windows Tkinter（通常随 Python 安装）。
- 串口转换器/下载线。默认上位机串口为 `COM14`，波特率 `115200`。

## 安装 Python 依赖

在仓库根目录执行：

```powershell
python -m pip install -r requirements.txt
```

如果电脑安装了多个 Python，请使用实际启动工作台的解释器：

```powershell
py -3 -m pip install -r requirements.txt
```

依赖包括 `pyserial`、`loguru` 和 `stm32loader`。

### 时间参数的查找与实际作用

2026-10-10按正式入口调用关系整理了时间参数，固件源码、标定数值和板上程序保持原样。v179后可编辑参数为182项：移出三项未使用的历史等待，补入三个实际使用的等待，并新增两项摄像头打靶高度；16个任务的126项专用等待全部保留。

| 要调整的内容 | 调参台位置 | 如何理解 |
| --- | --- | --- |
| 任务1／任务2直线速度 | 参数标定 → 各自直线速度组 | STEP半周期，单位μs，越小越快 |
| 旋转、毫米微调、起停曲线 | 参数标定 → 旋转与微调／加减速与距离判定 | 起停与巡航分开；每端曲线脉冲数0或1表示不启用曲线 |
| 升降速度和下降末段 | 参数标定 → 升降速度与末段 | 普通速度与下降末段分开；末段长度0表示无独立末段 |
| 某个完整抓取／放置任务的等待 | 任务等待时间 → 选中具体任务 | 专用字段按实际动作顺序排列；下方另列公共字段及使用次数 |
| 单独收回、张爪、转台等命令 | 任务等待时间 → 公共等待与独立命令 | 按实际mode说明等待来源，显示当前毫秒数 |
| 陀螺仪、通信、GUI超时 | 任务等待时间 → 系统通信与超时（只读） | 这些时间不控制机械速度，GUI超时也不表示任务停止 |
| 历史等待字段是否有效 | 任务等待时间 → 历史未使用参数（只读） | 只在源码中定义，没有执行引用，不能用来调当前任务 |

必须区分：舵机PWM脉宽（μs）决定位置；步进STEP半周期（μs）决定速度；动作等待（ms）决定何时执行下一步。等待0表示不等待，当前舵机等待输入范围0–5000ms；等待是固定延时，不是舵机位置反馈。

`SERVO_POWER_ON_SETTLE_MS`虽然名字含“POWER_ON”，当前正式上电并不执行它；它用于mode36前伸、mode52收回、mode70全张开和mode72初始化收尾，当前500ms。`SERVO1_SETTLE_MS`还被任务中的公共伸缩对位使用；`SERVO2_SETTLE_MS`还被任务1从舵盘放到赛场的最终全张开使用；`SERVO3_SETTLE_MS`用于单项转台和mode72开始回正，完整任务去盘／回正有各自等待。

抓取到舵盘的“升至安全高度后停留”发生在上升结束后；从盘取物的“夹紧后额外停留”发生在上升前。任务1从舵盘放到赛场的最终松爪等待是公共Servo2等待＋该任务额外等待A＋额外等待B，当前代码没有分段张爪。界面实时显示每个任务的舵机固定等待合计，另说明不包含升降、换向和通信时间。

三项历史字段 `SERVO3_HOME_BEFORE_CLAW_OPEN_MS`、`ARM_ACTION_HOLD_MS`、`GROUND_RELEASE_STAGE_INTERVAL_MS`已改为只读参考，不再写回。新增可编辑的实际字段是 `SERVO_POWER_ON_SETTLE_MS`、`CHASSIS_DIRECTION_SETTLE_MS`、`LIFT_DIRECTION_SETTLE_MS`；旧JSON方案缺少它们时保留当前读到的数值，旧历史字段会忽略并写入日志。

完整逐项清单：`diagnostics/20261010_time_parameter_audit/时间参数对应清单.txt`；机器可读记录及源码位置：`diagnostics/20261010_time_parameter_audit/timing_inventory.json`。

工作台默认读取 `USER/chassis_controller_main.c`，支持：

- Servo1/2/3、升降单项试动；

## 伸缩默认收回与舵盘对位

v177 已删除2350 us独立避让参数、30 mm分界及其升降联动。上电、初始化、地面抓取前收回、舵盘对位和 mode 52 均使用 `SERVO1_DISC_ALIGN_PULSE_US = 2455 us`。调参台只保留“默认收回 / 舵盘对位位置”和任务2前伸两个伸缩参数，当前参数总数为182。

普通升降及慢降只驱动升降 STEP，不因高度改变 Servo1；任务1圆柱与正方体堆叠放置均保持2455对位。任务2领奖台前伸仍使用已有 `SERVO1_TASK2_EXTEND_PULSE_US = 946 us`，升降也不会将这个任务位置自动收回。旧参数方案中的2350避让字段会被忽略，不能通过导入恢复已删除的联动。

mode 52（上位机 `MoveControl.grub_return()`；调参台“任务试跑 → Servo1 收回”）指令为 `FF 34 00 00 00 00 00 00 00 FE`，只写 TIM5_CH2，等待原有500 ms后返回 `FF 01 FE`。反馈表示命令处理完成，不是舵机位置反馈。

任务按动作阶段明确选择 Servo2 状态，任务1所有舵盘及任务2共用四个参数：

| 状态 | 宏 | 当前脉宽 | 使用阶段 |
| --- | --- | --- | --- |
| 夹紧 / 转运保持 | `SERVO2_CLAMP_PULSE_US` | 1460 us | 普通物块或奖杯夹住后，保持夹紧升降与转台；正方体有独立夹紧参数 |

| --- | --- |

mode16不再使用舵盘3专用1215，任务2取盘不再使用1173，地面放置不再经过1018中间角度。旧参数方案可继续导入，这三个旧字段不参与新任务；其余标定保持。地面全开后先等待 `SERVO2_SETTLE_MS`（当前380 ms），再等待原 `PUT*_STAGE_INTERVAL_MS`（当前100 ms，现表示额外保持）及 `PUT*_FINAL_OPEN_HOLD_MS`，随后回升。

此前mode42/43/44复用了任务1放盘163与转盘250，GUI标为任务1高度；调181只影响从盘取杯。v172为任务2独立接入两个新宏，初值复制原163/250，没有猜测实际避碰余量。转向舵盘5途中碰到已存杯，重点调转台旋转安全高度；对准盘位下降时发生干涉，则核对放入舵盘高度和机械间距。两个新参数供三块奖杯盘共用；任务1仍用原来的163/250。

GUI和固件均检查：任务2转盘高度必须高于放杯和取杯高度，取杯后回正高度必须高于取杯高度，且不得低于领奖台放置目标；各高度范围0–360mm。配置不满足时不执行任务2运动。数值顺序校验不代表实际已避开杯体/夹爪，仍需实测标定。旧178参数方案导入时，原冠军／亚军55／37mm会迁移为新的领奖台放置参数；摄像头高度保留当前源码值。

## 摄像头打靶高度与领奖台放置高度（v179）

## 元器件测试

打开“元器件测试”页，连接串口，点击“检测测试固件”。返回 `FF 07 FE` 后才允许使用新测试指令；旧固件会返回 `FF 00 FE`，此时应先烧录 v156。连接和固件检测不会发送运动指令。

页面支持四个车轮独立正反转、升降目标高度测试、三路舵机独立脉宽和 PE6 按键电平读取。每项动作需勾选上方运动范围确认并点击测试按钮；升降还需确认软件零点，转台还需确认旋转空间。可先把车轮架空，用默认 `200` 脉冲、`1000 μs` 半周期观察所选车轮。脉冲数上限 `3200`，元器件测试半周期范围为 `1–65535 μs`；升降目标范围为 `0–360mm`，不再限制单次最多移动 `10mm`。测试按数量自动结束。速度是名义值，串口轮询会增加少量时间。

“任务试跑 → 独立动作与初始化”有“夹爪单独闭合”按钮（mode71），使用当前 `SERVO2_CLAMP_PULSE_US` 夹紧值，只驱动夹爪。

同一页新增“底盘试跑”：直线距离默认 `5 cm`，允许 `±1–20 cm`，以及旋转角度默认 `10°`，允许 `±1–90°`。直线试跑使用 mode 1 前后移动命令，旋转试跑使用 mode 3 有符号角度旋转，不依赖元器件测试能力探测；两项都是阻塞式底盘命令，停止元器件测试按钮不能中断，必须先选择小范围并确认底盘周围无障碍。

| 元器件 | STEP / PWM | DIR | 单独控制 |
| --- | --- | --- | --- |
| 左前轮 MOTOR7 | PC8 | PA8 | mode 90，编号 7 |
| 右前轮 MOTOR4 | PC7 | PG8 | mode 90，编号 4 |
| 左后轮 MOTOR8 | PC9 | PC1 | mode 90，编号 8 |
| 右后轮 MOTOR3 | PC6 | PG7 | mode 90，编号 3 |
| 升降电机 | PB10 | PA4 | mode92，目标高度0–360mm |
| Servo1 伸缩 | PA1 / TIM5_CH2 | — | mode 94，编号 1 |
| Servo2 夹爪 | PA2 / TIM5_CH3 | — | mode 94，编号 2 |
| Servo3 转台 | PA3 / TIM5_CH4 | — | mode 94，编号 3 |
| PE6 按键 | PE6 输入 | — | mode 95，读取低/高电平 |

升降目标范围为 `0–360mm`，可以直接测试较大高度差。高度是发出的步数推算值，不含位置传感器反馈；上电前仍需人工放到底部。中途停止时固件保留不足1mm的步数，先在本页完成一次整数目标高度测试，才能恢复常规升降和抓放任务。

舵机脉宽范围 `500–2500 μs`，“使用当前标定值”只填入值，点击“发送脉宽”才运动。返回完成状态表示 PWM 已设置，不表示机械已到位。舵机持续输出该脉宽，直到新指令或停止；测试页不会改写源码标定值。Servo4 与 WS2812 共用 PA11，本页不启用此通道。

“停止元器件测试 / 关闭舵机信号”发送 mode 91，可在本页步进测试等待期间发送，返回 `FF 04 FE`。它将所有 STEP 置低并关闭三路舵机 PWM；驱动器共享 EN 保持原状态，升降电机仍保持使能。此按钮只中断元器件测试，不能中断原有阻塞任务。关闭或断开界面时，若测试仍在进行，会尝试发送停止；通信物理中断时无法保证收到停止，但步进测试仍按有限脉冲数结束。

PE6 读取返回 `FF 05 FE`（低/松开）或 `FF 06 FE`（高/按下），不会启用比赛启动。比赛启动 mode 89 之后，固件拒绝元器件运动测试，需复位后重新检测。测试页与“通信与构建日志”同时显示 TX/RX。**ACK 说明命令被处理，器件好坏仍需观察实物、电压和波形；系统不自动判定电路板或元器件合格。**

手动串口工具可使用 `FF + 8 字节 payload + FE`，多字节参数均为高字节在前：

| mode | payload（8 字节，未用位填 0） | 返回 |
| --- | --- | --- |
| 90 | `[90, 电机编号, DIR(0/1), 脉冲高, 脉冲低, 半周期高, 半周期低, 0]` | `FF 01 FE` 或停止 `FF 04 FE` |
| 91 | `[91, 0, 0, 0, 0, 0, 0, 0]` | `FF 04 FE` |
| 92 | `[92, 目标mm高, 目标mm低, 半周期高, 半周期低, 0, 0, 0]` | `FF 01 FE` 或停止 `FF 04 FE` |
| 93 | `[93, 0, 0, 0, 0, 0, 0, 0]` | `FF 07 FE` |
| 94 | `[94, 舵机编号, 脉宽高, 脉宽低, 0, 0, 0, 0]` | `FF 01 FE`（PWM 已设置） |
| 95 | `[95, 0, 0, 0, 0, 0, 0, 0]` | `FF 05 FE` / `FF 06 FE` |
| 70 | `[70, 0, 0, 0, 0, 0, 0, 0]` | `FF 01 FE`，地面全张开 |
| 71 | `[71, 0, 0, 0, 0, 0, 0, 0]` | `FF 01 FE`，按 `SERVO2_CLAMP_PULSE_US` 闭合 |

mode70/71是独立夹爪动作：70地面全张开；71按通用夹紧值闭合。调参台“任务试跑 → 独立动作与初始化”提供mode71按钮；上位机接口为 `MoveControl.grub_close()`。

例如左前轮 DIR 0、200 脉冲、1000 μs 半周期：`FF 5A 03 00 00 C8 03 E8 00 FE`；停止：`FF 5B 00 00 00 00 00 00 00 FE`。非法参数或锁定时返回 `FF 00 FE`。

离线检查可运行 `python -m unittest discover -s tests -v`：验证帧编码、参数边界、串口停止优先级、界面初始化和真实固件测试函数的模拟引脚行为。固件模拟测试需要 PATH 中存在 gcc；其他测试不连接真实串口。

## 上电启动流程

PE6 使用下拉输入，按下为高电平。上电后按键默认不触发任务；只有上位机完成机械初始化和陀螺仪归零并发送 mode 89 后，下一次有效按压才会上报 `FF 03 FE`。

```python
from upper_host_v86 import MoveControl

control = MoveControl("COM14", 115200)
control.initialize_and_wait_for_start()

# 收到 PE6 启动事件后，才从 Home 区域出发。
control.set_distance(x=0.6)
```

完整顺序为：等待 STM32 就绪 `FF 02 FE` → 机械初始化 mode 72 → 陀螺仪归零 mode 19 → 启用 PE6 mode 89 → 等待 `FF 03 FE` → 执行任务。mode 72 现在会在机械初始化真正完成后才返回 `FF 01 FE`，因此后续校准不会与初始化动作重叠。

## 引脚摘要

```text
上位机 UART1：PA9 TX、PA10 RX
陀螺仪 UART4：PC10 TX、PC11 RX
Servo1：TIM5_CH2 / PA1
Servo2：TIM5_CH3 / PA2
Servo3：TIM5_CH4 / PA3
升降 MOTOR1：PA4 DIR、PB10 STEP、PC5 EN
麦轮 STEP：PC6、PC7、PC8、PC9
```

Servo1/2/3 共用 TIM5，固件会先完成三通道配置并写入安全脉宽，再启动定时器，避免初始化阶段输出 0 us 无效脉冲。`HARDWARE/SERVO/servo.c` 保持 GBK/CP936 编码。Servo4 与 WS2812 都使用 TIM1_CH4 / PA11，存在资源冲突；当前正式入口不调用 `Servo4_Init()`。

## 安全说明

- 首次上电或复位后，固件中的软件升降高度从 `0 mm` 开始；执行升降/任务前应先把机构放到底部，并在工作台确认同步。
